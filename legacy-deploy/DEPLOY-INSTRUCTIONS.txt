 خطوات إصلاح مشكلة الحفظ في الإنتاج (erp.restocost.shop)
 المشكلة: حفظ الجرد اليومي rcerp_daily_counts لا يستجيب
=====================================================

السبب الجذري (مؤكد من التشخيص):
 1) ملف الخادم المرفوع على الاستضافة قديم ولا يتعرف على مفتاح
    rcerp_daily_counts (غير موجود في قائمة COLLECTION_KEYS)
    فيرفض الطلب بصمت.
 2) حد nginx الافتراضي لحجم الطلب = 1MB فقط، بينما بيانات
    الجرد اليومي أكبر من ذلك → يرجع 413 بدون رسالة واضحة.

محتويات هذه الحزمة:
 - dist/          ← الواجهة الجديدة (استبدل مجلد الواجهة الحالي كاملاً)
 - server/index.js← الخادم المحدث (يحتوي المفتاح + حد رفع 20MB)
 - server/package.json

=====================================================
 خطوات التنفيذ (بالترتيب)
=====================================================

[1] خذ نسخة احتياطية من الاستضافة أولاً
    - حمّل نسخة من مجلد الواجهة الحالي وملف server/index.js القديم
    - وإن كانت البيانات مخزنة كملفات JSON على الخادم، انسخها أيضاً

[2] ارفع الملفات الجديدة
    - ارفع محتوى مجلد  dist/  إلى مجلد الواجهة على الاستضافة
      (احذف القديم أولاً لتجنب ملفات JS قديمة متبقية)
    - استبدل  server/index.js  بالملف المرفق

[3] أعد تشغيل تطبيق Node
    - عبر PM2:      pm2 restart restocost
    - أو من لوحة الاستضافة: زر Restart أمام التطبيق

[4] عدّل إعداد nginx (مهم جداً - سبب رئيسي للمشكلة)
    داخل بلوك server { } أو location الخاص بالموقع أضف:

        client_max_body_size 20m;

    ثم نفّذ:
        nginx -t && nginx -s reload

[5] التحقق من نجاح الإصلاح
    - افتح erp.restocost.shop واضغط F12 ← تبويب Network
    - أدخل جرداً يومياً واحفظ
    - يجب أن ترى الطلب:
        POST /api/collections/rcerp_daily_counts   →   200 OK
    - إن ظهر 413 → حد nginx لم يُطبق بعد (راجع الخطوة 4)
    - إن ظهر 404/400 → الخادم القديم ما زال يعمل (راجع الخطوة 3)

[6] لو استمرت المشكلة
    - شاهد سجلات الخادم مباشرة:  pm2 logs restocost --lines 50
    - تأكد أن المسار المرفوع هو نفسه الذي يشغّله pm2
      (pm2 describe restocost ← عمود script path)
