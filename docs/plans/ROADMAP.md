## البنية التحتية (يدعم كل ما سبق)

- [x] ترحيل SQLite → PostgreSQL + Prisma — قاعدة `restocost2` (محلياً على المنفذ 5433)، نموذج علائقي أولي (branches/suppliers/raw_materials/recipes/inventory_items/users) + جدول KV JSONB كامل يحافظ على واجهة `getKV/setKV` المتزامنة؛ سكربت `npm run migrate:pg` + Tree fallback إلى SQLite عند غياب DATABASE_URL
- [x] Repository Pattern + Unit of Work + اختبارات (Vitest) — `server/repository.mjs` (`CollectionRepository` + `UnitOfWork`): دمج بالمعرّف يحترم _mtime وشواهد الحذف، دفعة واحدة آتومية عبر `setKVMany` (معاملة PG واحدة / SQLite BEGIN…COMMIT)، مع 11 اختبار Vitest + 24 node --test
- [x] CDC/مزامنة تنبثق لتعويض _mtime الحالي (offline-first) — `change_log` جدول بتنسيق seq متزايد لكل كتابة (set/del)، غلاف `cdcSince(since)` في store (PG عبر نفس قائمة الكتابة التسلسلية + SQLite)، endpoint `/api/sync/cdc?since=` للأجهزة لسحب "ما تغيّر" بدل الكل، watermark في sync-state، + 7 اختبارات Vitest
- [x] تكامل jsreport كمحرك تقارير (HTML→PDF) — يعيد استخدام أسلوب V1 للطباعة RTL بلا لغة جديدة، على نفس Express/Prisma — أُنجز ضمن "مصمّم التقارير الموحّد" (بند 72): محرك jsreport 3.13.0 مثبّت في `server/` + Chromium (Chrome النظام) + endpoint `/api/report` يعمل بوضعي الجدول والقالب المخصص
- [ ] Read Replica للتقارير الثقيلة
