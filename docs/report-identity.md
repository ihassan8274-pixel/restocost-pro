# هوية التقارير — مستمدة من تصميم "RestoCost Pro v7.0"

> المصدر المعياري: `E:\MASSOBI APP\COST REPROT` — تطبيق مرجعي (Vue 3) يحتوي تصميم التقارير الاحترافي لكل شاشات التكاليف والمصروفات والفروع.
> قائد: كل تقرير في منظومة التقارير المتطورة (77) **يستمد هويته** — الاسم، المقاييس، الفلاتر، البنية — من هذا التصميم، لا من قوالب مرتجلة.

## 1. بصمة التقرير (البنية القياسية المستمدة من v7.0)

كل شاشة تقرير تتوافق مع:

| العنصر | المواصفة المستمدة |
|---|---|
| العنوان | عنوان عربي + إنجليزي (معرّف) + أيقونة في الواجهة |
| بطاقات KPI | 4–7 بطاقات أعلى التقرير (قيمة كبيرة + تسمية + لون دلالي) |
| الفلاتر | شهر + فرع (اختيار متعدد) + علامة (حيث يلزم) — دائمة أعلى الصفحة |
| الجدول | صفوف البيانات + صف «الإجمالي» + تلميح الألوان (أزرق=معياري/أخضر=ربح/أحمر=انحراف) |
| التصدير | Excel متعدد أوراق + طباعة/PDF برأس الشركة (الاسم، الشعار، الشعار النصي، لون أساسي، رسالة رأس) |
| رقم التقرير | تلقائي `RPT-xxxxxx` (مستمد من النموذج التنفيذي) |
| الروابط | روابط سريعة للمصادر (مثل /expenses ← `/pl`)، ومستخدمة في القوائم ذات الصلة |

## 2. مصطلحات موحدة (مستمدّة من كشوف v7.0)

`رصيد أول ← إجمالي متاح (رصيد أول + مشتريات + تحويلات) ← رصيد آخر = تكلفة المبيعات الفعلية` — تُستخدم بثبات في تقارير المخزون والاستهلاك (هذه هي جذور `theoretical_vs_actual`).

## 4. تطبيق الهوية (النموذج المنفذ)

- منفذ بالفعل بهذه الهوية: `cogs_recipe`، `cogs_category`، `cogs_branch`، `margin_analysis`، `purchases_register`، `theoretical_vs_actual` (كلها تطبق البصمة: KPI + فلاتر شهر/فرع + Excel + طباعة برأس الشركة).
- **`theoretical_vs_actual`** (منفذ بمصدر `src/components/advanced-reporting/reports/TheoreticalVsActualReport.tsx`): النظري = الوصفات (BOM + هالك%) × مبيعات الفترة مع تقسيم وصفات الخدمة على `yieldPieces` وتحويل وحدات التداول لوحدة المخزون؛ الفعلي = وارد الفترة (مشتريات/تحويلات) − صافي تغير رصيد الفترة عبر حركات المخزون (تعادل رصيد أول + مشتريات + تحويلات − رصيد آخر)؛ فرق كمي/قيمي لكل مادة + نسبة مطابقة% لكل تصنيف. فلاتر: شهر + فرع + تصنيف.
- **`food_cost_trend12`** (منفذ بمصدر `src/components/advanced-reporting/reports/FoodCostTrendReport.tsx`): نسبة تكلفة الطعام الشهرية = Σ تكلفة ÷ Σ إيراد × 100 (تجميع ثم نسبة — لا متوسط النسب)، حتى آخر 12 شهراً أو بسنة محددة، مع منحنى هدف متقطع (متوسط targetFoodCostPercent للوصفات النشطة) في رسم مجمّع (أعمدة إيراد + خط نسبة + ReferenceLine هدف) وجدول شهري بفرق عن السابق وعن الهدف وشارة حالة، ومؤشر فروع. فلاتر: سنة + فرع.
- **`branch_scorecard`** (منفذ بمصدر `src/components/advanced-reporting/reports/BranchScorecardReport.tsx`): مقارنة مؤشرات تشغيلية مجمعة لكل فرع في فترة واحدة حسب مرجع `/insights` (best/worst): إيراد صافي ← تكلفة طعام (نسبة/هدف) ← هدر ← هامش مساهمة% ← عمالة ← تشغيل ← صافي ربح% ← نقطة تعادل (تكلفة ثابتة ÷ معامل المساهمة) وهامش أمان%، مع Δ% عن الشهر السابق، وترتيب (إيراد/نسبة طعام/ربح/كمية) وبطاقات أفضل/أسوأ فرع ورسم أعمدة المجموع. فلاتر: شهر + فرع.
- **`period_over_period`** (منفذ بمصدر `src/components/advanced-reporting/reports/PeriodOverPeriodReport.tsx`): مقارنة فترتين متتاليتين حسب مرجع `/insights` (mom): نمو% وفرق لكل مؤشر (إيراد صافي ناتج بخصم ضريبة 15%، كمية، سجلات) ونسبة الطعام لكل فترة = Σ تكلفة ÷ Σ إيراد ثم فرقهما بالنقاط؛ رسم أعمدة الإيراد + خطي النسبة للمحورين، جدول فرعي، صف إجمالي. فلاتر: فترتان + فرع.
- **`profit_center_pl`** (منفذ بمصدر `src/components/advanced-reporting/reports/ProfitCenterPLReport.tsx`): قائمة دخل رسمية حسب مرجع `/pl` + `/company-pl` لمركز واحد أو الشركة مجمعة: المبيعات خام ← ضريبة ← صافي ← تكلفة طعام ← هدر ← هامش مساهمة ← عمالة ← تشغيل ← صافي ربح، بكل بند نسبته من صافي المبيعات، + التكلفة الأولية (طعام+عمالة)% ونقطة التعادل وهامش الأمان؛ بطاقات KPI ورسم لكل مركز وقائمة مراكز قابلة للمقارنة. فلاتر: شهر + مركز.
- **`price_history_material`** (منفذ بمصدر `src/components/advanced-reporting/reports/PriceHistoryReport.tsx`): سلسلة أسعار من سندات الاستلام المعتمدة (GRN) حسب مرجع `/procurement` «أفضل سعر»: متوسط مرجح (Σ سعر×كمية ÷ Σ كمية)، آخر/أدنى/أعلى سعر، تذبذب%، انحراف كل سند عن المتوسط، منحنى خطي + جدول سجل + مقارنة الموردين (أفضل سعر). فلاتر: مادة + مورد.
- **`stock_movements`** (منفذ بمصدر `src/components/advanced-reporting/reports/StockMovementsReport.tsx`): كشف حركات المخزون التفصيلي (وارد = Σ موجبات الدلتا، صادر = Σ سالبات، صافي) تجميع بنوع الحركة والسند والفرع والمادة، رسم أعمدة وارد/صادر، خلاصة الأنواع + كشف محدّث بفلاتر. فلاتر: شهر + فرع + مادة + نوع حركة.
- **`inventory_valuation`** (منفذ بمصدر `src/components/advanced-reporting/reports/InventoryValuationReport.tsx`): تقييم الرصيد = كمية × آخر سعر استلام معتمد (GRN) — وإلا سعر شراء الوحدة/القياسي — تجميع بالفرع والتصنيف (مفتاح التصنيف)، قيمة ونسب توزيع ورسم أعمدة. فلاتر: شهر (آخر تحديث) + فرع.
- **`distributions`** (منفذ بمصدر `src/components/advanced-reporting/reports/DistributionsReport.tsx`): مراجعة توزيعات البوت (مرجع شاشة التوزيع): جودة المطابقة لكل رسالة (تلقائي = exact+alias، تقريبي = fuzzy، غير مطابق = none، أهداف مجهولة = unknownTargets)، تغطية%، كميات موزعة بوحدة المخزون، الحالة (معتمد/محوّل/معلق/مرفوض) ورسم مكدّس. فلاتر: شهر + حالة.
